## Introduction

Besides the specific use-case in this project, the repo structure aims to demonstrate a well defined and structured project setup for deep-learning based segmentation tasks.

This project uses machine learning to segment and detect rock joint traces in images. Rock joints are fractures in the rock mass that can have a significant impact on the stability of the rock mass. The detection of rock joints is important for geotechnical analysis and rock mass quality evaluation. Rock joints can be observed as surfaces or traces on the surface of a rock mass. Previous works from the authors have contributed to semi-automatically extract rock joint surfaces from 3D point clouds using a "click-plane-detect" process implemented in the proprietary Maptek sofware. However, joint traces covering a small number of image-pixels (in reality a big proportion of rock joints), are difficult to be extracted directly based on geometrical post-processing of 3D point clouds.

Several recent studies use `semantic segmentation` with supervised machine learning to detect the rock joints with high detection accuracy. However, a major challenge is that the labelling process of rock joint traces is a subjective and laborious. Besides, the ground truth of these dataset cannot not be 100% correct. Addressing the issue of impossible to achieve 100% correct ground truth of previous studies, we novelly evaluate the performance of models trained on synthetic data, on real-world data. Building the synthetic dataset and evaluation the ML model is described in the following paper:

> Chiu, J. K. Y., Hansen, T. F., Paulsen, E. M. (2025). Automated rock joint trace mapping using a supervised learning model trained on synthetic data generated by parametric modelling Preprint on arXiv: [https://arxiv.org/abs/2501.01234](https://arxiv.org/abs/2501.01234)

`Semantic segmentation` is a computer vision task where the goal is to classify each pixel in an image into a category. In this project, we use semantic segmentation to classify each pixel in an image as either a rock joint trace or not a rock joint trace. We have implementd training for the following semantic segmentation networks:

- DeepLabV3Plus (https://arxiv.org/abs/1802.02611)
- UNet++ (https://arxiv.org/abs/1807.10165)
- FracSegNet
- CrackSegDiff?

**Hypothesis**:
A machine learning model trained exclusively on a synthetic dataset can effectively detect rock joints in natural rock mass images.

**Objective**:
To develop a synthetic dataset of rock joints suitable for training a generalisable machine learning model for detecting natural rock joints. The hypothesis will be validated by training the model on the synthetic dataset and evaluating its performance on real rock joint images.

Performance will be evaluated numerically using `segmentation metrics` and qualitatively overlaying the `predicted mask` on the original image.

## Datasets

**Syntethic DFN dataset**: A syntetic dataset generated with FracMan software and Rhino/Grasshopper script. FracMan is a state-of-the-art Discrete Fracture Network (DFN) software. We aim at generating DFNs that comprises of a wide range of block forms and joint systems, so that the training data can be as generalised as possible. The labels for the dataset is produced automatically using a Grasshopper script, and is thus perfect and non-subjective.

*Rationale for dataset*: Training a generalised ML-model based on a purely synthetic dataset. A dataset with perfect labels to verify the implementation of the ML-models.

**Synthetic box dataset**: A dataset of synthetic "box" images generated using Grasshopper script. The labels for these images are perfect.

*Rationale for dataset*: A second approach to training a generalised ML-model based on a purely synthetic dataset. Unlike the DFN dataset, the box dataset is simpler, more controlled and `can be validated in real life`.A dataset with perfect labels to verify the implementation of the ML-models.

**Real-world rock slope dataset**: A dataset of real-world images of rock joints from rock cuttings in Larvik and RV-4 project in Norway. The rock cuttings are located in two different geologic regions. The rock joints are mapped manually but the resulting labels are semi-automated using a process developed in Grasshopper and Rhino. Due to the manually rock joint mapping process and artifacts in rendering of the 3D models, the labels are not perfect. This is a key dataset to demonstrate the syntetic dataset generation technique.

*Rationale for dataset*: The core dataset to evaluate the performance of the ML-models trained on synthetic data, on real-world data. A successful result will partly (because of the subjectivity involved in labelling) be a verification of the hypothesis

**Real-world box dataset**: A real world dataset of physical cardboard-boxes with manually labelled gaps between boxes, imitating rock joint traces but in a controlled setting. The labelled data will be nearly perfect and thus allow an quantitative evaluation.

*Rationale for dataset*: A real-life dataset with perfect labels to verify the implementation of the ML-models. Is less complex and natural than `real-world rock slope dataset`, but is a second approach to verify the implementation of the ML-models.

## Training strategies

Variations for training and evaluation on the synthetic dataset:

1. *Verification of implementation*. Testing that the ML-implementation works as intended on a synthetic dataset. Choose the best model/algorithm based on the performance on this dataset. Run hyperparameter optimization to find the best hyperparameters for this model. Compare performance of 3-4 algorithms.
    - Verificaion 1 - Train and validate (train/test split or crossvalidation) on the "synthetic box dataset".
    - Verification 2 - Train and validate (train/test split or crossvalidation) on the "synthetic DFN dataset".

2. *Main objective - the DFN approach*.
    - Validation type 1. Train on the "synthetic DFN dataset" and test on the "real world rock slope dataset". *This result will be the main validation of the hypothesis.*
    - Validation type 2. Train on the "synthetic DFN dataset" and test on the "real world box dataset"

3. *Main objective - the box approach*.
	- Validation type 1. Train on the "synthetic box dataset" and test on the "real world rock slope dataset"
	- Validation type 2. Train on the "synthetic box dataset" and test on the "real world box dataset"


EXTRA:

4. *Dataset-size test*: Train and validate only on the `synthetic DFN dataset` using different sizes of the dataset, and test on `real-world rock slope dataset`. The goal is to demonstrate the effect of different number of samples.

5. *Semi-supervised learning*: Semi-supervised or self-supervised learning (i.e. do not use the labels) on the `synthetic DFN dataset` (perhaps filtered to more easily show joints in the image). Use a few labelled samples in the end to finetune the model. Evaluate separately on the `real-world box dataset` and the `real-world rock slope dataset`. This is the second strategy in trying to handle the problem of the label-effort and imperfect labelling. Compare results with the fully supervised models.

6. *One-shot segmentation* One-shot segmentation on the `real-world rock slope dataset`. The goal is to investigate the quality of such an effort.

For all models, experiment with transfer learning using pretrained models as a backbone model. At least for DeepLabV3+ and Unet, different pretrained models are available.

## Metrics for evaluation

- **IoU (Intersection over Union)**: IoU is calculated as the ratio of the intersection of the predicted and true positive pixels to the union of the predicted and true positive pixels. The IoU metric is a measure of the overlap between the predicted and true positive pixels and is used to evaluate the accuracy of the model in detecting rock joints in the image.

- **Dice Coefficient**: The Dice Coefficient is calculated as the ratio of twice the intersection of the predicted and true positive pixels to the sum of the predicted and true positive pixels. The Dice Coefficient is a measure of the similarity between the predicted and true positive pixels and is used to evaluate the accuracy of the model in detecting rock joints in the image. It’s sensitive to how well the model captures fine details

- **Precision and Recall**: Precision indicates how many of the predicted joint traces are accurate, while recall shows how many of the true joint traces were detected. Balancing these metrics is key for generalising to different rock masses, as some joints may be subtle and easily missed (low recall) or overestimated (low precision)

We illustrate the prediction mask images qualitatively in `fiftyone`, where the predicted mask is overlaid on the original image. This allows us to visually inspect the model's performance and identify any potential issues with the model's predictions.

## Installation

### Prerequisites

- Python 3.11.1+
- [pyenv](https://github.com/pyenv/pyenv)
- [Poetry](https://python-poetry.org/)

### Setting Up the Environment

1. **Install pyenv**:

    - **Install pyenv in Linux**:

        ```sh
        curl https://pyenv.run | bash
        ```

        Add the following to your `~/.bashrc` or `~/.zshrc`:

        ```sh
        export PATH="$HOME/.pyenv/bin:$PATH"
        eval "$(pyenv init --path)"
        eval "$(pyenv init -)"
        eval "$(pyenv virtualenv-init -)"
        ```

        Restart your shell:

        ```sh
        exec "$SHELL"
        ```

    - **Install pyenv in Windows**:

        ```sh
        Invoke-WebRequest -UseBasicParsing -Uri "https://raw.githubusercontent.com/pyenv-win/pyenv-win/master/pyenv-win/install-pyenv-win.ps1" -OutFile "./install-pyenv-win.ps1"; &"./install-pyenv-win.ps1"
        ```

2. **Install Python**:

    ```sh
    pyenv install 3.11.1
    pyenv local 3.11.1
    ```

3. **Install Poetry**:

    ```sh
    curl -sSL https://install.python-poetry.org | python3 -
    ```

    Add Poetry to your PATH:

    ```sh
    export PATH="$HOME/.local/bin:$PATH"
    ```

4. **Install Project Dependencies**:

    ```sh
    poetry install
    ```

5. **Activate the Virtual Environment**:

    ```sh
    poetry shell
    ```

6. **Install Pre-Commit Hooks**:

    ```sh
    poetry run pre-commit install
    ```

## Usage

### Train and Evaluate the Model

```sh
python scripts/train.py
```

Use hydra configuration options with train.py to specify different datasets, models and training parameters. For example, to train a model with DeepLabV3 architecture training on `synthetic_box`, evaluating on `synthetic_box`and tracking all information to mlflow, use the following command:

```sh
python scripts/train.py model=deeplabv3 dataset_train=[synthetic_box] dataset_test=[synthetic_box] log_mlflow=True
```

See all options with:

```sh
python scripts/train.py --help
```

You can stop the training process at any time by pressing `Ctrl + C`. The training process will then be stopped but all the tracking information will be saved in mlflow.


### Training the model in azure-cloud

1. Log in to the Azure cloud node using SSH, e.g `ssh tfh@az-cluster.oslo.ngi.no` and standard NGI password.
2. Install poetry and pyenv on the Azure cloud machine
3. Clone the repository
4. Install the environment with poetry install
5. Make sure that the home area is mounted
5. Run the shell script which runs the training

```sh
azure_cloud_train.sh
```

Inside the shell script there is a call to the python script. Make sure to change the initial path to the project

```sh
poetry run python scripts/train_eval.py path_project=/home/tfh/synthetic-rock-joint-generation-for-ml
```

### Inspect the experiment results in MLflow

The experiments directory is stored in a shared location, so you can inspect the results of the experiments by running the following command:

```sh
cd experiments
mlflow ui
```

Open the web interface at `http://localhost:5000` to view and inspect the results.


### Hydra configuration details

To run a script without saving hydra configuration files (i.e. for testing purposes), use the following command:

```sh
python scripts/train.py hydra.run.dir=NUL hydra.output_subdir=null
```

To run a script in debug mode, use the following command:

```sh
HYDRA_FULL_ERROR=1 python scripts/train.py
```


### Special functionality

Check if we have enough samples to get the full potential of the model based on the syntetic dataset. The script will train several machine learning models using different amounts of samples and plot the results. If the model performance converge to a certain value, it indicates that we have enough samples to get the full potential of the model.

```sh
python scripts/check_samples.py
```
